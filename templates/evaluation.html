CRISP-ML · PHASE 04

Model Evaluation

This stage evaluates the performance and generalization ability of the Machine Learning models developed for the Predictive Maintenance System. It compares classification algorithms, analyzes prediction errors, and selects the most suitable model for identifying potential equipment failures.

01. Evaluation Overview

Purpose of Model Evaluation

Model Evaluation determines how effectively machine learning algorithms predict equipment failures using operational variables such as air temperature, process temperature, rotational speed, torque, and tool wear.

The evaluation process compares predicted values with actual target values. It examines both classification performance and the model's ability to generalize to observations that were not used during training.

This stage is essential because incorrect predictions can affect maintenance decisions. In particular, undetected failures and unnecessary alerts must be analyzed before considering real industrial use.

Evaluation Objective

Compare Logistic Regression, Decision Tree, and Random Forest using stratified five-fold cross-validation, select the best-performing algorithm according to mean F1-score, and evaluate the selected model on an independent test dataset.

02. Evaluation Strategy

Testing and Model Selection Process

The dataset was divided into training and testing subsets using an 80% and 20% split. The process used random_state = 42 and stratification to preserve the proportion of failure and non-failure observations.

  • Prepare the selected input features and target variable.
  • Separate the training and independent testing subsets.
  • Compare three classification algorithms.
  • Apply stratified five-fold cross-validation to the training data.
  • Select the model using the highest mean cross-validation F1-score.
  • Train the selected pipeline using the complete training subset.
  • Evaluate final performance using the independent test subset.

Evaluation Dataset

Data separation: The independent testing subset was not used for model selection or cross-validation. Preprocessing was included inside each model pipeline to prevent information leakage between training and validation folds.

03. Evaluation Metrics

Metrics Used

Five evaluation metrics were used to assess the classification models. Because the dataset contains substantially more non-failure observations than failure observations, Accuracy alone is not enough to evaluate model performance.

  • Accuracy: Proportion of all predictions that were correctly classified.
  • Precision: Proportion of predicted failures that were actual failures.
  • Recall: Proportion of actual failures correctly identified.
  • F1-score: Harmonic mean of Precision and Recall.
  • ROC-AUC: Ability to distinguish between failure and non-failure classes across different classification thresholds.

The Receiver Operating Characteristic (ROC) curve illustrates the relationship between the True Positive Rate and the False Positive Rate at different classification thresholds.

The Area Under the Curve (AUC) provides an overall measure of the model's ability to distinguish between failure and non-failure observations.

06. Data Imbalance and Performance Analysis

Class Distribution

The complete dataset contains an imbalance between non-failure and failure observations. There are 9,661 non-failure records and only 339 failure records.

Target Class Records Percentage
No Failure (0) 9,661 96.61%
Failure (1) 339 3.39%

This imbalance makes failure detection more challenging. A model could achieve high Accuracy by predicting the majority class while failing to identify a considerable number of actual failures.

For this reason, Precision, Recall, and F1-score are particularly important for evaluating the minority failure class.

Interpretation of Model Performance

  • The model correctly identified 52 actual machine failures.
  • The model missed 16 actual failure cases.
  • The model generated 41 false positive predictions.
  • Recall of 76.47% shows that approximately three quarters of actual failures were detected.
  • Precision of 55.91% indicates that false alarms remain an important limitation.
  • Accuracy of 97.15% should be interpreted together with the other metrics because of class imbalance.

Comparison of Machine Learning Algorithms

Three classification algorithms were evaluated: Logistic Regression, Decision Tree, and Random Forest. Stratified five-fold cross-validation was applied using only the training dataset.

Cross-Validation Methodology

Cross-validation was used to evaluate model performance across different subsets of the training data. This provides a more reliable comparison than relying on a single validation split.

  • Cross-validation technique: Stratified K-Fold.
  • Number of folds: 5.
  • Shuffle enabled with random_state = 42.
  • Evaluation performed on the training subset.
  • Preprocessing included inside each model pipeline.
  • The independent test subset was reserved for final evaluation.

Selected Model: Random Forest

Random Forest achieved the highest mean cross-validation F1-score of 63.80%. It also obtained the highest cross-validation ROC-AUC of 96.61%.

Therefore, Random Forest was selected for final training and independent testing. The selection criterion was the highest mean cross-validation F1-score, which balances Precision and Recall.

08. Overfitting and Generalization

Overfitting Analysis

Overfitting occurs when a model learns patterns specific to the training data but performs less effectively on unseen observations.

The Random Forest model achieved a training F1-score of 84.95% and a final testing F1-score of 64.60%.

The difference of approximately 20.35 percentage points suggests a possible overfitting problem. Additional evaluation with new data is necessary to understand the cause and its impact.

Generalization

Generalization describes the model's ability to maintain predictive performance when analyzing observations that were not included during training.

The five-fold cross-validation produced a mean F1-score of 63.80% for Random Forest. Its independent test F1-score was 64.60%.

These results provide initial evidence of similar performance between cross-validation and the independent test set. However, the difference between training and testing performance requires further attention.

Evaluation limitation: The difference between training and testing performance is a possible overfitting signal, not definitive proof. Further testing with additional operational data is recommended before using the model in real industrial environments.

10. Domain Validation and Practical Limitations

Industrial Relevance

The model is intended to support predictive maintenance by identifying patterns associated with possible equipment failures.

Its predictions should be interpreted as decision-support information. They do not replace professional inspections, maintenance procedures, or technical diagnosis.

The AI4I 2020 dataset used in this project is a simulated dataset. Therefore, the reported results should not be interpreted as proof of equivalent performance in a real industrial plant.

Domain Expert Feedback

Feedback from a person with industrial maintenance knowledge has not yet been collected. This remains a pending validation activity.

A future consultation should review the relevance of the selected variables, the interpretation of predicted failures, the consequences of false alarms, and the practical usefulness of the model's outputs.

Validation status: Quantitative model evaluation has been completed using the available dataset. Independent validation with real operational data and feedback from an industrial domain expert remain pending.

11. Final Model Assessment

Model Selection and Reliability

Three algorithms were compared using stratified five-fold cross-validation. Random Forest was selected because it achieved the highest mean F1-score of 63.80%.

The selected model was then evaluated on an independent test subset containing 2,000 observations. It achieved 97.15% Accuracy, 55.91% Precision, 76.47% Recall, 64.60% F1-score, and 96.56% ROC-AUC.

The model identified 52 of the 68 actual machine failures. However, 16 failures remained undetected and 41 false positive predictions were generated.

These results demonstrate the model's potential for predictive maintenance while highlighting the importance of improving failure detection and reducing false alarms.

The model should be considered a decision-support tool rather than a replacement for professional maintenance inspections.

Recommendations for Improvement

  • Evaluate the model using additional real-world operational data.
  • Investigate methods to reduce false negatives and false positive alerts.
  • Review classification thresholds according to maintenance requirements and operational costs.
  • Perform additional experiments with hyperparameter optimization.
  • Collect feedback from industrial maintenance specialists.
  • Monitor model performance after deployment and retrain when justified by new evidence.

Phase Conclusion

The Model Evaluation stage compared three classification algorithms using stratified five-fold cross-validation.

Random Forest was selected because it achieved the highest mean cross-validation F1-score of 63.80%. The final model was evaluated using 2,000 independent testing observations.

The final results were 97.15% Accuracy, 55.91% Precision, 76.47% Recall, 64.60% F1-score, and 96.56% ROC-AUC.

The confusion matrix and ROC curve provide visual evidence of the evaluation results. The comparison of training and testing performance also identified a possible overfitting limitation.

Although the selected model demonstrates promising classification ability, false negatives, false positives, class imbalance, and the use of simulated data remain important considerations.

The next stage, Model Deployment, focuses on integrating the evaluated model into the Flask application and making its prediction functionality available to users.
