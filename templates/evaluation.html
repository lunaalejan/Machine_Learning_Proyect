CRISP-ML · PHASE 04

Model Evaluation

This stage evaluates the performance and generalization ability of the selected Random Forest model for the Predictive Maintenance System. It analyzes classification results, prediction errors, and the model's ability to identify potential equipment failures using independent testing data.

01. Evaluation Overview

Purpose of Model Evaluation

Model Evaluation determines how effectively the selected machine learning model predicts equipment failures using operational variables such as air temperature, process temperature, rotational speed, torque, and tool wear.

The evaluation process compares predicted values with actual target values. It examines classification performance and the model's ability to generalize to observations that were not used during training.

This stage is essential because incorrect predictions can affect maintenance decisions. In particular, undetected failures and unnecessary alerts must be analyzed before considering real industrial use.

Evaluation Objective

Evaluate the selected Random Forest model using an independent test dataset, analyze its prediction errors, and determine whether its performance is suitable for the predictive maintenance prototype.

02. Evaluation Strategy

Independent Testing Process

The dataset was divided into training and testing subsets using an 80% and 20% split. The process used random_state = 42 and stratification to preserve the proportion of failure and non-failure observations.

  • Use the previously selected Random Forest pipeline.
  • Keep the independent testing subset separate from training.
  • Generate predictions using the 2,000 test observations.
  • Compare predicted labels with the actual target values.
  • Calculate classification metrics and analyze prediction errors.
  • Review the results to assess generalization performance.

Evaluation Dataset

Dataset Subset Records Percentage Purpose
Training 8,000 80% Model training and cross-validation
Testing 2,000 20% Independent final evaluation
Total 10,000 100% Complete dataset

Data separation: The independent testing subset was not used for model selection or cross-validation. Preprocessing was included inside the model pipeline to prevent information leakage between training and validation folds.

03. Evaluation Metrics

Metrics Used

Five evaluation metrics were used to assess the selected classifier. Because the dataset contains substantially more non-failure observations than failure observations, Accuracy alone is not enough to evaluate model performance.

  • Accuracy: Proportion of all predictions that were correctly classified.
  • Precision: Proportion of predicted failures that were actual failures.
  • Recall: Proportion of actual failures correctly identified.
  • F1-score: Harmonic mean of Precision and Recall.
  • ROC-AUC: Ability to distinguish between failure and non-failure classes across different classification thresholds.

06. Data Imbalance and Performance Analysis

Class Distribution

The original dataset contains 10,000 observations, with 9,661 non-failure cases and 339 failure cases. This represents an imbalanced classification problem.

Class Observations Percentage
No failure (0) 9,661 96.61%
Failure (1) 339 3.39%

Impact on Model Performance

Accuracy alone is not sufficient to evaluate this model because the majority class represents most observations. For this reason, Precision, Recall, F1-score and ROC-AUC are also considered.

The classifier uses class_weight="balanced" to account for the different class frequencies during training.

Performance Interpretation

The Recall of 76.47% shows that the model identifies most of the failure cases in the test set. The Precision of 55.91% indicates that some predicted failures are false alarms and require further consideration before real-world implementation.

07. Overfitting and Generalization

Training and Testing Performance

The difference between training and test F1-score is approximately 20.35 percentage points. This gap may indicate overfitting or differences in performance between the training and test samples.

Further validation with additional datasets and real operational information would be necessary to determine how the model performs in practical industrial conditions.

09. Domain Validation and Practical Limitations

Dataset and Validation Context

The project uses the AI4I 2020 Predictive Maintenance Dataset, which is a simulated dataset designed for predictive maintenance research. Its results should not be interpreted as proof of performance on actual industrial equipment.

Current Limitations

  • The dataset does not represent verified operational measurements from the project's own industrial environment.
  • The failure class is relatively small compared with the non-failure class.
  • The model generates false positive predictions.
  • Long-term performance and data drift have not yet been evaluated.
  • Validation by an industrial domain expert has not yet been documented.

Practical recommendation: Before operational use, the model should be evaluated with real equipment data and reviewed by qualified maintenance personnel. Their feedback can help determine whether the predictions are useful for maintenance decisions.

10. Final Model Assessment

Evaluation Result

The Random Forest classifier achieved an Accuracy of 97.15%, Recall of 76.47%, F1-score of 64.60% and ROC-AUC of 96.56% on the independent test dataset.

These results indicate that the model can identify a substantial proportion of failure cases in the AI4I 2020 dataset. Nevertheless, its Precision and the observed training-test F1-score difference highlight areas that require further improvement and validation.

Final Evaluation Decision

The Random Forest model is retained as the selected model for the project's prototype deployment. Its use in real industrial operations requires additional validation with real-world data.

Selected model: Random Forest

Phase Conclusion

The evaluation phase measured the selected model using an independent test dataset and multiple classification metrics. The results support the use of Random Forest in the current predictive maintenance prototype, while also identifying limitations related to false alarms, class imbalance and generalization.
