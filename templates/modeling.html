CRISP-ML · PHASE 03

Model Engineering

This stage describes the development of the Machine Learning model for the Predictive Maintenance System. It covers the classification approach, algorithm selection, preprocessing pipeline, training process, hyperparameter configuration, validation, and model serialization.

01. Modeling Overview

Purpose of Model Engineering

Model Engineering focuses on developing a Machine Learning solution capable of identifying patterns in industrial equipment operating data and using those patterns to estimate the possibility of machine failure. The development process uses the prepared AI4I 2020 dataset and the selected input variables established during the previous Data Engineering stage. The objective is to build a classification model that can be integrated into the Flask application and generate predictions from equipment operating conditions.

Modeling Objective

Develop a supervised classification model that learns from historical equipment observations and predicts the binary target variable Machine failure.

02. Machine Learning Approach

Supervised Binary Classification

The project uses supervised learning because the AI4I 2020 dataset contains labeled observations. Each observation includes operating measurements and a corresponding machine failure indicator. The model learns the relationship between input variables and the target variable during training. After learning these patterns, it can estimate the failure class for new observations.

  • Learning type: Supervised Learning.
  • Task: Binary Classification.
  • Input: Machine operating conditions.
  • Output: Failure or No Failure.
  • Target: Machine failure.

03. Model Selection

Selected Algorithm: Random Forest

Random Forest is the classification algorithm implemented in the Predictive Maintenance System. It is an ensemble learning method that combines predictions from multiple decision trees to produce a final classification. This algorithm can model complex relationships between numerical and categorical equipment variables. It also supports class weighting, which is useful when the target classes are imbalanced.

Decision Trees

Tree-based models divide observations according to variable conditions and generate predictions through a sequence of decision rules.

Random Forest

Random Forest combines multiple decision trees, helping reduce the instability associated with relying on a single tree. This is the algorithm implemented in the current project.

Model selection: Random Forest is the implemented algorithm. A comparison with other algorithms has not been documented in the supplied training script. Its performance is evaluated using the independent testing subset.

04. Input Features and Target

Variables Used by the Model

The training script uses six input variables describing the equipment type and its operating conditions. The target variable represents whether a failure occurred in the original observation.

Variable Role Description
Type Input Machine variant: L, M, or H.
Air temperature [K] Input Ambient temperature in Kelvin.
Process temperature [K] Input Process temperature in Kelvin.
Rotational speed [rpm] Input Machine speed in rpm.
Torque [Nm] Input Applied torque in Nm.
Tool wear [min] Input Accumulated wear in minutes.
Machine failure Target Failure (1) or No Failure (0).

Excluded variables: UDI and Product ID are identification fields. TWF, HDF, PWF, OSF, and RNF are failure-mode indicators. They are excluded from the input features to prevent the model from receiving information that could reveal the target.

06. Preprocessing and Hyperparameter Configuration

Data Preprocessing Pipeline

The project uses a ColumnTransformer to apply different preprocessing operations according to the feature type. The categorical variable Type is encoded, while numerical variables are passed through without additional scaling.

Feature type Transformation Configuration
Categorical OneHotEncoder handle_unknown="ignore"
Numerical Passthrough Original numeric values
preprocessor = ColumnTransformer( transformers=[ ( "categorical", OneHotEncoder(handle_unknown="ignore"), categorical_features ), ( "numerical", "passthrough", numerical_features ) ] )

Pipeline Implementation

The preprocessing component and Random Forest classifier are combined into a single Scikit-learn Pipeline. This ensures that the transformations are fitted using training data and consistently applied to testing data and future predictions.

pipeline = Pipeline( steps=[ ("preprocessor", preprocessor), ("classifier", model) ] ) pipeline.fit(X_train, y_train)

Data leakage prevention: Because preprocessing is part of the Pipeline, its fitting occurs during pipeline.fit() using X_train. The testing data is not used to fit the encoder.

Hyperparameter note: These are the configured values in train_model.py. The supplied script does not implement an automated hyperparameter search or tuning procedure.

07. Model Validation

Testing on Unseen Observations

After training, the model generates predictions using the independent testing subset. These predictions are compared with the actual target values to measure classification performance. The script calculates Accuracy, Precision, Recall, F1-score, and ROC-AUC. It also generates a confusion matrix and ROC curve.

  • Evaluate predictions on 2,000 testing observations.
  • Review correct and incorrect classifications.
  • Examine the model's ability to identify failure cases.
  • Generate classification metrics and visualizations.

Validation Implementation

predictions = pipeline.predict(X_test) probabilities = pipeline.predict_proba(X_test)[:, 1] accuracy = accuracy_score(y_test, predictions) precision = precision_score(y_test, predictions) recall = recall_score(y_test, predictions) f1 = f1_score(y_test, predictions) roc_auc = roc_auc_score(y_test, probabilities)

Connection with Model Evaluation

The metrics and graphical results generated during the training procedure are analyzed in the next stage, Model Evaluation. The project uses Accuracy, Precision, Recall, F1-score, ROC-AUC, the confusion matrix, and the ROC curve to examine classification performance.

Validation limitation: The supplied training script uses a single stratified train/test split. It does not implement cross-validation. The testing subset is used for the reported evaluation metrics.

08. Model Saving and Integration

Model Serialization

After training and evaluation, the complete Pipeline is saved using the Joblib library. Saving the complete pipeline preserves both the preprocessing component and the trained Random Forest classifier. This allows the prediction module to load the same transformations and model without repeating the training process.

MODEL_PATH = MODEL_DIR / "failure_model.joblib" joblib.dump(pipeline, MODEL_PATH)
Joblib Serialization library

Training Module

train_model.py loads the dataset, prepares the features, trains the pipeline, evaluates predictions, generates graphical evidence, and saves the model artifact.

Prediction Module

predict.py loads the saved pipeline and generates predictions from the equipment values supplied through the Flask application.

Integration: The saved artifact contains the fitted preprocessing transformations and classifier. Therefore, new prediction inputs must follow the same feature structure used during training.

Phase Conclusion

The Model Engineering stage establishes the actual development and training procedure of the predictive classification model. The project implements a Random Forest classifier integrated with a preprocessing pipeline. The training procedure uses a stratified 80/20 split, OneHotEncoder for categorical data, and passthrough for numerical variables. The classifier uses 200 estimators, a maximum depth of 12, a minimum split of 5, balanced class weights, and a random state of 42. The complete pipeline is saved using Joblib and integrated into the prediction module of the Flask application. The next stage, Model Evaluation, examines the model's predictive performance through classification metrics, graphical evidence, and analysis of its ability to identify machine failures.
