CRISP-ML · PHASE 04

Model Engineering

This stage describes the development of the Machine Learning model for the Predictive Maintenance System. It covers the classification approach, algorithm selection, training process, model configuration, validation, and model serialization.

01. Modeling Overview

Purpose of Model Engineering

Model Engineering focuses on developing a Machine Learning solution capable of identifying patterns in industrial equipment operating data and using those patterns to estimate the possibility of machine failure. The development process uses the prepared AI4I 2020 dataset and the selected input variables established during the previous Data Preparation stage. The objective is to build a classification model that can be integrated into the Flask application and used to generate predictions from equipment operating conditions.

Modeling Objective

Develop a supervised classification model that learns from historical equipment observations and predicts the binary target variable Machine failure.

02. Machine Learning Approach

Supervised Binary Classification

The project uses supervised learning because the AI4I 2020 dataset contains labeled observations. Each observation includes operating measurements and a corresponding machine failure indicator. The model learns the relationship between the input variables and the target variable during training. After learning these patterns, it can estimate the failure class for new observations.

  • Learning type: Supervised Learning.
  • Task: Binary Classification.
  • Input: Machine operating conditions.
  • Output: Failure or No Failure.
  • Target: Machine failure.

03. Model Selection

Selected Algorithm: Random Forest

Random Forest is the classification algorithm initially implemented in the Predictive Maintenance System. It is an ensemble learning method that combines predictions from multiple decision trees to produce a final classification. The algorithm is suitable for exploring relationships between numerical and categorical equipment variables and can model complex patterns in the data.

Decision Trees

Tree-based models divide observations according to variable conditions and generate predictions through a sequence of decision rules.

Random Forest

Random Forest combines multiple decision trees, helping reduce the instability associated with relying on a single tree.

Model selection: Random Forest is the model already implemented in the project. Its final selection should be supported by the evaluation results and, if additional algorithms are tested, by a comparison of their performance.

04. Input Features and Target

Variables Used by the Model

The prediction module receives six input variables describing the equipment type and its operating conditions. The target variable represents whether a failure occurred in the original observation.

Variable Role Description
Type Input Machine variant: L, M, or H.
Air temperature Input Ambient temperature in Kelvin.
Process temperature Input Process temperature in Kelvin.
Rotational speed Input Machine speed in rpm.
Torque Input Applied torque in Nm.
Tool wear Input Accumulated wear in minutes.
Machine failure Target Failure (1) or No Failure (0).

05. Model Training Process

Training Workflow

Model training consists of providing the algorithm with prepared observations so that it can identify patterns between equipment operating conditions and machine failure. The training workflow includes the following activities:

  • Load the prepared dataset.
  • Separate input features from the target variable.
  • Apply the required data transformations.
  • Divide the dataset into training and testing subsets.
  • Initialize the Random Forest classifier.
  • Train the model using the training observations.
  • Generate predictions using the testing data.
  • Save the trained model for future use.

Implementation evidence: The actual training procedure should be documented using the project's train_model.py file. The exact split configuration and preprocessing steps must match the implemented code.

06. Hyperparameter Configuration

Random Forest Configuration

Random Forest uses hyperparameters that control the structure of the decision trees and the behavior of the ensemble. These settings influence the complexity of the model, its learning behavior, and its ability to generalize to unseen observations.

Hyperparameter Function
n_estimators Number of decision trees in the forest.
max_depth Maximum depth allowed for each tree.
random_state Controls reproducibility of random operations.
class_weight Can adjust the importance assigned to each class.
min_samples_split Minimum observations required to split a node.

Configuration note: The table describes available Random Forest hyperparameters. It does not claim that all of them were configured or optimized in the current project. The actual values must be obtained from train_model.py.

07. Model Validation

Validation Strategy

Model validation helps determine whether the trained classifier can generalize beyond the observations used during training. The testing subset is used to generate predictions that can later be compared with the actual target values. This process provides the basis for evaluating the model's performance in the next methodological stage.

  • Evaluate predictions on unseen observations.
  • Review correct and incorrect classifications.
  • Examine the model's ability to identify actual failure cases.
  • Check for possible overfitting.
  • Document the evaluation configuration and results.

Connection with Model Evaluation

The validation results obtained during model development will be analyzed in the next stage, Model Evaluation. Metrics such as Accuracy, Precision, Recall, F1-score, and ROC-AUC will be used to assess classification performance.

08. Model Saving and Integration

Model Serialization

After training, the model is saved so that it can be loaded later without repeating the entire training process. The project uses the Joblib library to serialize the trained model into a file that can be accessed by the prediction module.

failure_model.joblib

The prediction module loads the saved model and uses it to process new equipment operating values submitted through the Flask application.

Training Module

train_model.py is responsible for the model training process and saving the resulting artifact.

Prediction Module

predict.py loads the saved model and generates predictions from the values supplied by the user.

Phase Conclusion

The Model Engineering stage establishes the development and training process of the predictive classification model. Random Forest is the algorithm currently implemented in the Predictive Maintenance System. Its trained model is saved using Joblib and integrated into the prediction module developed in Python. The next stage, Model Evaluation, will examine the model's predictive performance through classification metrics, graphical evidence, and analysis of its ability to identify machine failures.
