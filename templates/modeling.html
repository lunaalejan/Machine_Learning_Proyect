CRISP-ML · PHASE 03

Model Engineering

This phase describes the development of the Machine Learning models for the Predictive Maintenance System. It covers algorithm selection, model configuration, training, preprocessing integration, cross-validation, experimental comparison, model selection, and model serialization.

01. Modeling Overview

Purpose of Model Engineering

Model Engineering focuses on developing Machine Learning solutions capable of identifying patterns in industrial equipment operating data and estimating the probability of machine failure.

The development process uses the AI4I 2020 dataset and six selected input variables established during the Data Engineering stage.

Three supervised classification algorithms were implemented and compared to identify the most suitable model for integration into the Flask application.

Modeling Objective

Develop, train, and compare supervised classification models that learn from historical equipment observations and predict the binary target variable Machine failure. The selected model must provide a useful balance between detecting failures and limiting false alarms.

02. Machine Learning Approach

Supervised Binary Classification

The project uses supervised learning because the AI4I 2020 dataset contains labeled observations. Each observation includes operating measurements and a corresponding machine failure indicator.

During training, the algorithms learn relationships between the input variables and the target variable. Once trained, the model can estimate the failure probability for new equipment observations.

  • Learning type: Supervised Learning.
  • Task: Binary Classification.
  • Input: Machine operating conditions.
  • Output: Failure or No Failure.
  • Target: Machine failure.
  • Dataset: AI4I 2020 Predictive Maintenance.

Prediction scope: The model estimates failure probability based on the six available input features. It does not establish the exact time when a failure will occur.

03. Algorithm Selection and Justification

Algorithms Evaluated

Three classification algorithms were implemented to compare their ability to identify equipment failures. All models use the same training subset and preprocessing strategy, allowing a consistent comparison.

Logistic Regression

A linear classification algorithm used as a baseline. It estimates the relationship between input variables and the probability of belonging to a failure class. It provides a reference against which more complex models can be compared.

Decision Tree

A tree-based algorithm that divides observations according to feature conditions. It generates predictions through decision rules and can represent nonlinear relationships between operating measurements and failure outcomes.

Random Forest

An ensemble learning method that combines multiple decision trees. It can represent complex relationships and uses class weighting to account for the imbalance between failure and non-failure observations.

Selection Strategy

The three algorithms were compared using stratified five-fold cross-validation. The highest mean F1-score was selected as the primary model selection criterion.

Selection rationale: Random Forest was selected because it achieved the highest mean cross-validation F1-score among the three evaluated algorithms.

04. Input Features and Target

Variables Used by the Models

The training script uses six input variables describing machine type and operating conditions. The target variable represents whether a failure occurred in the original observation.

Variable Role Description
Type Input Machine variant: L, M, or H.
Air temperature [K] Input Ambient temperature in Kelvin.
Process temperature [K] Input Process temperature in Kelvin.
Rotational speed [rpm] Input Machine speed in revolutions per minute.
Torque [Nm] Input Applied torque in Newton-meters.
Tool wear [min] Input Accumulated tool wear in minutes.

Excluded variables: UDI and Product ID are identification fields. TWF, HDF, PWF, OSF, and RNF are failure-mode indicators. These variables are excluded from the input features to prevent the model from receiving information that could reveal the target.

06. Preprocessing and Pipeline Configuration

Data Preprocessing Pipeline

The project uses a ColumnTransformer to apply different preprocessing operations according to feature type. The categorical variable Type is encoded using OneHotEncoder, while numerical variables are standardized using StandardScaler.

Feature type Transformation Configuration
Categorical OneHotEncoder handle_unknown="ignore"
Numerical StandardScaler Standardization of numerical features
preprocessor = ColumnTransformer( transformers=[ ( "categorical", OneHotEncoder(handle_unknown="ignore"), categorical_features ), ( "numerical", StandardScaler(), numerical_features ) ] )

Pipeline Implementation

Each algorithm is combined with its preprocessing component in a Scikit-learn Pipeline. This ensures that preprocessing transformations are fitted independently inside each training fold during cross-validation and applied consistently to testing observations.

pipeline = Pipeline( steps=[ ("preprocessor", preprocessor), ("classifier", classifier) ] )

Data leakage prevention: Because preprocessing is part of the Pipeline, its transformations are fitted using the corresponding training data. Validation and testing observations are not used to fit preprocessing transformations.

08. Model Experiments and Comparison

Experimental Methodology

The three algorithms were evaluated using stratified five-fold cross-validation on the 8,000 training observations. The following values represent the mean scores across the five validation folds.

The experiment uses the same input features, preprocessing structure, training subset, and evaluation metrics for each algorithm.

Model Accuracy Precision Recall F1-score ROC-AUC
Random Forest 97.19% 56.72% 73.06% 63.80% 96.61%
Decision Tree 96.80% 53.14% 63.12% 57.22% 81.02%
Logistic Regression 82.25% 13.74% 80.44% 23.46% 89.65%

Cross-Validation Configuration

  • Validation method: Stratified K-Fold.
  • Number of folds: 5.
  • Shuffle: Enabled.
  • Random state: 42.
  • Primary selection metric: Mean F1-score.
  • Additional metrics: Accuracy, Precision, Recall, and ROC-AUC.
cv = StratifiedKFold( n_splits=5, shuffle=True, random_state=42 ) scoring = { "accuracy": "accuracy", "precision": "precision", "recall": "recall", "f1": "f1", "roc_auc": "roc_auc" }

Experiment Conclusion: Random Forest

Random Forest obtained the highest mean cross-validation F1-score of 63.80%, followed by Decision Tree with 57.22% and Logistic Regression with 23.46%.

Random Forest also achieved the highest mean cross-validation ROC-AUC of 96.61%. It was therefore selected for final training and independent testing based on the predefined F1-score selection criterion.

Interpretation: Logistic Regression achieved higher recall than the other models during cross-validation, but its precision and F1-score were substantially lower. Random Forest provided a more balanced combination of precision and recall according to the selected F1-score criterion.

09. Model Selection and Final Training

Selection Criterion

The final algorithm is selected by sorting the cross-validation comparison results according to mean F1-score in descending order.

comparison_df = comparison_df.sort_values( by="CV F1-score", ascending=False ).reset_index(drop=True) best_model_name = comparison_df.iloc[0]["Model"] pipeline = models[best_model_name] pipeline.fit(X_train, y_train)

Once selected, the Random Forest pipeline is fitted again using the complete training subset of 8,000 observations. The independent test subset remains reserved for the final evaluation.

Selected Model: Random Forest

Random Forest was selected because it achieved the highest mean F1-score across the five cross-validation folds. Its ensemble structure and class weighting make it a suitable candidate for the imbalanced classification task.

11. Domain Knowledge and Practical Considerations

Industrial Maintenance Context

Predictive maintenance aims to identify conditions associated with equipment failure before an unexpected breakdown occurs. The model uses temperature, rotational speed, torque, machine type, and tool wear as indicators of operating conditions.

In a practical maintenance environment, the interpretation of predictions should consider equipment specifications, operating limits, maintenance history, and the judgment of qualified maintenance personnel.

Domain Expert Validation

A formal evaluation by an industrial maintenance specialist has not yet been documented in this project. Therefore, no expert approval or professional validation is claimed.

A future validation activity should review whether the selected input variables, model predictions, false alarms, and missed failures are meaningful for real equipment maintenance decisions.

Dataset limitation: AI4I 2020 is a simulated predictive maintenance dataset. Its results do not independently demonstrate performance on real industrial equipment. Operational validation is required before using the model for maintenance decisions.

12. Model Saving and Integration

Model Serialization

After training and evaluation, the selected pipeline is saved using the Joblib library. Saving the complete pipeline preserves both the fitted preprocessing component and the trained Random Forest classifier.

This allows the prediction module to load the same transformations and model without repeating the training process.

13. Modeling Limitations and Future Improvements

Technical Limitations

  • The dataset contains an imbalanced distribution between failure and non-failure observations.
  • Random Forest shows a noticeable difference between training and testing F1-score, suggesting possible overfitting.
  • Precision indicates that some predicted failures are false alarms.
  • The model comparison was performed using predefined configurations. Automated hyperparameter optimization was not performed.
  • Additional validation with real industrial equipment data is required before operational use.
  • Formal feedback from an industrial maintenance specialist remains a pending validation activity.

Future Improvements

  • Evaluate additional model configurations through a documented hyperparameter search.
  • Investigate strategies to improve the balance between precision and recall.
  • Evaluate model performance with real equipment measurements and maintenance records.
  • Collect domain expert feedback on the usefulness of model predictions.
  • Monitor model performance and investigate retraining when justified by new data.

Phase Conclusion

The Model Engineering stage established the development and training procedure of the predictive classification system.

Three supervised classification algorithms were implemented and compared: Logistic Regression, Decision Tree, and Random Forest. The comparison used stratified five-fold cross-validation on the training subset.

Random Forest was selected because it achieved the highest mean cross-validation F1-score of 63.80%.

The selected model uses 200 estimators, a maximum depth of 12, a minimum split of 5, balanced class weights, a random state of 42, and all available CPU cores.

The complete preprocessing and classification pipeline is saved using Joblib and integrated into the prediction module of the Flask application.

The next stage, Model Evaluation, examines predictive performance through classification metrics, graphical evidence, confusion matrix, ROC analysis, and the model's ability to identify machine failures.
