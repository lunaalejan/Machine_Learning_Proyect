CRISP-ML · PHASE 06

Monitoring and Maintenance

This phase defines how the Predictive Maintenance System and its Machine Learning model should be monitored, evaluated, maintained, and updated over time. The objective is to identify changes in data quality, detect possible model performance degradation, maintain application reliability, and establish procedures for continuous improvement.

01. Monitoring Objectives

Purpose of Model Monitoring

Once a Machine Learning model is integrated into an application, its performance and reliability must be reviewed regularly. Operating conditions, equipment characteristics, and input data may change over time. These changes can affect the quality of predictions.

The Predictive Maintenance System establishes a monitoring strategy to verify that the model continues to process equipment information correctly and provides useful predictions for maintenance decision support.

  • Monitor the quality and consistency of input data.
  • Review the distribution of generated predictions.
  • Identify possible changes in equipment operating conditions.
  • Evaluate model performance when verified outcomes become available.
  • Monitor application errors and prediction availability.
  • Define procedures for model updates and maintenance.

Monitoring Strategy

The monitoring process combines data quality checks, prediction tracking, model performance evaluation, and application reliability reviews. These activities help identify problems early and provide information for maintenance and improvement decisions.

02. Operational and Performance Indicators

Key Performance Indicators (KPIs)

The following indicators are proposed to evaluate the behavior of the predictive maintenance application and its Machine Learning model. They provide a structured way to review system activity and identify possible issues.

Indicator Description Purpose
Prediction Volume Number of predictions generated by the application during a specific period. Understand system usage and prediction activity.
Predicted Failure Rate Percentage of predictions classified as potential failures. Identify changes in the frequency of high-risk predictions.
Input Data Quality Presence of missing values, invalid measurements, and unexpected categories. Ensure that input information is suitable for prediction.
Model Precision Proportion of predicted failures that correspond to actual failures, when verified labels are available. Review false alarms.
Model Recall Proportion of actual failures correctly identified by the model. Review the number of missed failures.
F1-score Harmonic mean of precision and recall. Evaluate the balance between false alarms and missed failures.
Data Drift Changes in the statistical distribution of input variables compared with training data. Detect changes in the data received by the model.
Application Reliability Availability, prediction errors, and application response failures. Ensure the application operates correctly.

03. Data Quality Monitoring

Input Data Validation

The model depends on six input features: machine type, air temperature, process temperature, rotational speed, torque, and tool wear. Each prediction must be based on valid and consistently formatted information.

Before generating a prediction, the application should verify that the required values are present, that numerical fields contain valid numbers, and that the machine type belongs to the expected categories.

  • Verify that all required input fields are completed.
  • Check that numerical measurements are valid numbers.
  • Verify that machine type belongs to L, M, or H.
  • Identify unexpected or physically implausible measurements.
  • Prevent incomplete or invalid records from being processed.
  • Keep records of validation errors for later review.

Data Quality Control Procedure

1

Data Reception

Receive equipment measurements through the application prediction form or connected data source.

2

Input Validation

Check required fields, numerical formats, categorical values, and possible invalid measurements.

3

Prediction Processing

Send valid input information to the saved preprocessing and classification pipeline.

4

Result Recording

Record prediction information and relevant errors when logging is configured and enabled.

5

Periodic Review

Review input quality and identify recurring validation problems.

04. Data Drift and Model Performance Degradation

Data Drift Detection

Data drift occurs when the statistical characteristics of incoming data change compared with the data used during model training. These changes may affect the reliability of predictions.

For this project, monitoring should focus on the six model input variables: Type, Air temperature, Process temperature, Rotational speed, Torque, and Tool wear.

  • Compare new input distributions with the training dataset.
  • Review changes in numerical feature averages and ranges.
  • Check whether machine type frequencies change.
  • Identify unusual values or new operating conditions.
  • Investigate significant changes before deciding to retrain.

Model Performance Degradation

Model performance degradation occurs when predictions become less reliable over time. It can be identified by comparing predictions with verified real outcomes after equipment inspections or maintenance reports become available.

When actual failure labels are available, the team should calculate precision, recall, F1-score, and ROC-AUC using the new verified observations.

Special attention should be given to recall, because missed equipment failures may lead to unexpected operational interruptions.

Important Limitation

A prediction by itself does not confirm whether a machine has actually failed. Model performance cannot be measured reliably without verified outcomes. Therefore, predictions should be compared with maintenance inspections, equipment reports, or other confirmed failure records.

05. Monitoring Frequency and Responsibilities

Monitoring Schedule

The following schedule is a proposed initial monitoring plan. The review frequency can be adjusted according to application usage, the availability of operational data, and project requirements.

Frequency Monitoring Activity Responsible Role
Daily / During use Review application errors, invalid inputs, and prediction execution problems. System Administrator
Weekly Review prediction activity, input data quality, and generated alerts. Project / Data Team
Monthly Review feature distributions, possible data drift, and model performance when verified labels are available. Machine Learning Team
When an incident occurs Investigate prediction errors, data problems, or application failures. Responsible Technical Team
When necessary Evaluate retraining and deployment of an updated model. Machine Learning Team

Responsibilities

  • System Administrator: reviews application availability, errors, and technical operation.
  • Machine Learning Team: evaluates model performance, input distributions, and possible retraining.
  • Maintenance Personnel: verify equipment conditions and provide confirmed maintenance outcomes.
  • Project Team: documents monitoring activities, incidents, results, and system updates.

06. Model Retraining and Update Criteria

When Should the Model Be Retrained?

Retraining should be considered when new, verified operational data indicates that the current model may no longer represent equipment behavior adequately. Retraining must be based on evidence rather than on an arbitrary decision.

  • Significant changes are detected in input data distributions.
  • Verified evaluation results show a relevant decrease in model performance.
  • New types of equipment or operating conditions are introduced.
  • Maintenance records reveal failure patterns not represented in training data.
  • Data quality problems have been corrected and additional reliable observations are available.

Model Update Procedure

1

Collect New Verified Data

Gather new equipment measurements and confirmed failure outcomes.

2

Validate and Prepare Data

Review missing values, duplicates, inconsistencies, and data quality before training.

3

Train a Candidate Model

Apply the documented preprocessing and training procedure using appropriate training and validation data.

4

Evaluate the Candidate

Compare the new model with the current model using consistent evaluation metrics and an independent test set.

5

Approve and Deploy

Deploy the updated model only after its performance, compatibility, and reliability have been reviewed.

6

Document the New Version

Record the model version, training date, dataset, parameters, and evaluation results.

07. Risks and Quality Controls

Potential Risks

Risk Possible Impact Control / Mitigation
Incorrect Input Data Unreliable or invalid predictions. Validate required fields, formats, and measurement values.
Data Drift New operating conditions may reduce prediction reliability. Compare new data with training distributions.
False Negative Predictions Potential failures may remain undetected. Monitor recall and require equipment inspection.
False Positive Predictions Unnecessary inspections or maintenance activities. Review precision and confirm results with maintenance personnel.
Application Failure Users may be unable to generate predictions. Review application errors, logs, and deployment health.
Outdated Model The model may not represent current equipment behavior. Evaluate performance and retrain when justified.

Human Supervision

Machine Learning predictions must be treated as decision-support information. A high-risk prediction should lead to equipment inspection or technical review, not to an automatic conclusion that a failure has occurred. Final maintenance decisions should remain under the responsibility of qualified personnel.

08. Incident Reporting and User Feedback

Incident Management Procedure

When a problem is detected, the team should document the event, investigate its cause, and define corrective actions. This procedure helps maintain traceability and prevents recurring problems.

1

Incident Identification

Identify prediction errors, invalid input data, application failures, or unexpected results.

2

Incident Documentation

Record the date, affected function, description, available evidence, and possible impact.

3

Technical Investigation

Review input information, application logs, model behavior, and the circumstances of the event.

4

Corrective Action

Correct data problems, repair application errors, or evaluate the need for a model update.

5

Verification and Closure

Test the correction, document the outcome, and close the incident when the issue is resolved.

User Feedback Procedure

Maintenance personnel should be able to communicate whether a prediction was useful, whether an inspection confirmed a failure, or whether an alert was incorrect. This feedback can help improve future model evaluation and maintenance decisions.

  • Collect feedback about incorrect or unexpected predictions.
  • Record confirmed equipment inspection results.
  • Document false alarms and missed failures.
  • Review feedback during periodic monitoring meetings.
  • Use verified information to evaluate future model updates.

Feedback must be reviewed and validated before it is used as training data.

The test should also examine how the application handles invalid or incomplete input values and whether prediction information can be reviewed afterward.

Prediction Review Review the generated prediction in the application. The prediction result can be viewed correctly.

10. Monitoring Limitations

Current Project Limitations

The current system is an academic predictive maintenance prototype developed using the AI4I 2020 simulated dataset. Its monitoring strategy describes the procedures required for future operation, but it does not imply that the application is already connected to real industrial equipment or continuous sensor streams.

  • The training dataset contains simulated industrial observations.
  • Real-time sensor monitoring is not assumed to be implemented.
  • Performance monitoring requires verified failure outcomes.
  • Data drift detection requires new operational data for comparison.
  • Automatic retraining is not assumed to be implemented.
  • Monitoring frequency and responsibilities are proposed for the project.

Phase Conclusion

The Monitoring and Maintenance phase establishes a structured approach for maintaining the Predictive Maintenance System after deployment. It defines operational indicators, data quality controls, data drift detection, performance evaluation, monitoring responsibilities, retraining criteria, and incident management procedures.

Continuous monitoring is important because changes in equipment operating conditions and incoming data may affect model reliability. Periodic reviews and verified maintenance outcomes provide the information needed to evaluate whether the model remains useful.

By defining these procedures, the project provides a foundation for responsible maintenance, continuous improvement, and future validation using real industrial operational data.
