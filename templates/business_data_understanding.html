CRISP-ML · PHASE 01

Business and Data Understanding

This phase establishes the business problem, project objectives, stakeholders, dataset characteristics, and the feasibility of developing a Machine Learning solution for predictive maintenance.

01. Project Context

Project Overview

Predictive Maintenance System is a web-based application designed to support industrial maintenance activities through Machine Learning techniques. The project uses equipment operating variables to estimate the possibility of machine failure. It integrates a predictive model developed in Python with a Flask application, allowing users to register equipment, manage maintenance records, review alerts, and obtain failure predictions.

Industrial Context

Industrial equipment operates under different conditions involving temperature, rotational speed, torque, and component wear. Changes in these operating conditions may be associated with equipment failures. Unexpected failures can interrupt production processes, increase maintenance expenses, and affect operational efficiency. Predictive maintenance uses equipment data to support more informed maintenance decisions.

02. Business Problem

Problem Statement

Industrial maintenance teams may face difficulties identifying potential equipment failures before they occur. When maintenance activities depend mainly on fixed schedules or responses after a failure, equipment problems may remain undetected until they affect operations. This project addresses the challenge by developing a data-driven system capable of analyzing operating conditions and estimating the likelihood of machine failure.

Business Need

Provide a technological tool that helps maintenance personnel identify possible failure risks, review equipment information, and support maintenance planning using Machine Learning predictions.

03. Project Objectives

General Objective

Develop a predictive maintenance system that integrates Machine Learning and web technologies to estimate potential industrial equipment failures based on operating data and support maintenance decision-making.

Specific Objectives

  • Analyze the AI4I 2020 Predictive Maintenance Dataset.
  • Identify relevant variables associated with machine failure.
  • Develop and train a classification model.
  • Evaluate model performance using classification metrics.
  • Integrate the predictive model into a Flask web application.
  • Provide equipment management, maintenance records, and alert functionalities.

04. Machine Learning Objectives

Machine Learning Problem Definition

The Machine Learning component is formulated as a supervised binary classification problem. The model analyzes machine operating conditions and predicts whether a machine failure may occur.

  • Learning type: Supervised Learning.
  • Task: Binary Classification.
  • Target variable: Machine failure.
  • Class 0: No machine failure.
  • Class 1: Machine failure.
  • Selected algorithm: Random Forest Classifier.

Expected Model Output

The model returns a failure prediction and an estimated failure probability. This information is used to indicate a risk level and support maintenance decisions. The prediction is intended as decision support and does not replace professional equipment inspection.

06. Data Source

AI4I 2020 Predictive Maintenance Dataset

The project uses the AI4I 2020 Predictive Maintenance Dataset. It contains simulated industrial data designed to represent equipment operating conditions and machine failures. The dataset is used to develop and evaluate the predictive classification model.

  • Dataset file: ai4i2020.csv
  • Number of observations: 10,000
  • Number of columns: 14
  • Target: Machine failure
  • Data format: CSV

07. Dataset Structure

Dataset Variables

The dataset contains identifiers, machine characteristics, operating measurements, and failure-related variables. The following table describes the main variables used by the prediction model.

Variable Type Description
Type Categorical Machine variant: L, M, or H.
Air temperature [K] Numerical Ambient air temperature.
Process temperature [K] Numerical Temperature of the machine process.
Rotational speed [rpm] Numerical Machine rotational speed.
Torque [Nm] Numerical Rotational force applied to the machine.
Tool wear [min] Numerical Accumulated tool wear time.
Machine failure Binary Indicates whether a machine failure occurred.

08. Variables Used by the Prediction Model

Selected Input Features

The prediction model receives six input variables that describe the machine type and its operating conditions.

Input variable Unit / Format Purpose
Type L / M / H Identifies the machine variant.
Air temperature Kelvin (K) Describes ambient temperature.
Process temperature Kelvin (K) Describes process temperature.
Rotational speed Revolutions per minute (rpm) Describes machine rotation.
Torque Newton meters (Nm) Describes applied rotational force.
Tool wear Minutes (min) Describes accumulated tool wear.

Target variable: Machine failure. This is the outcome the model is designed to predict; it is not entered as a prediction input.

09. Initial Data Exploration

Exploratory Data Analysis (EDA)

Initial data exploration helps understand the distribution of the variables, identify patterns, examine relationships between measurements, and detect possible data quality problems before model development.

  • Examine the distribution of machine failures and non-failures.
  • Analyze air and process temperature distributions.
  • Examine rotational speed and torque values.
  • Analyze the distribution of tool wear.
  • Explore relationships between operating variables and machine failure.
  • Identify possible class imbalance in the target variable.

Failure Distribution

The dataset contains 9,661 observations without machine failure and 339 observations with failure. This indicates an imbalanced target distribution.

Operating Variables

Temperature, rotational speed, torque, and tool wear describe the operating conditions represented in the dataset.

10. Data Quality Assessment

Data Quality Checks

Before model development, the dataset must be examined to identify inconsistencies that could affect the results. The following checks are considered during data inspection.

Quality Check Purpose Evidence
Missing values Identify incomplete observations. Null-value count.
Duplicate records Identify repeated observations. Duplicate count.
Data types Verify numerical and categorical formats. Column data types.
Value ranges Identify unusual or invalid values. Descriptive statistics.
Target distribution Identify possible class imbalance. Class frequencies.

11. Data Limitations and Feasibility

Dataset Limitations

  • The dataset is based on simulated industrial operating conditions.
  • Its observations may not represent all types of real industrial equipment.
  • The failure patterns do not cover every possible real-world failure.
  • Model performance depends on the quality and representativeness of available data.
  • Additional testing with real operational data is necessary before production use.

Technical Feasibility

The project is technically feasible using Python, Pandas, Scikit-learn, Flask, and the available dataset. The trained model can be integrated into the web application to process equipment measurements and return predictions.

Success Criteria

The project aims to develop a functional application that can process equipment data, generate failure predictions, present model evaluation results, and support maintenance-related activities. Model quality is assessed using classification metrics, including precision, recall, F1-score, and ROC-AUC.

Phase Conclusion

The Business and Data Understanding phase establishes the industrial problem, project objectives, stakeholders, data source, relevant variables, and dataset limitations. The AI4I 2020 dataset provides the information required to develop a supervised classification model for predictive maintenance. These findings provide the foundation for the next phase: Data Engineering, where the dataset is cleaned, transformed, and prepared for Machine Learning training.
