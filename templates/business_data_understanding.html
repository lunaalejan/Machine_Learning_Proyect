CRISP-ML · PHASE 01

Business and Data Understanding

This phase defines the industrial maintenance problem, business objectives, Machine Learning goals, stakeholders, data characteristics, and feasibility of developing a predictive maintenance solution.

01. Project Context

Project Overview

Predictive Maintenance System is a web-based application designed to support industrial maintenance activities through Machine Learning techniques.

The project analyzes equipment operating variables to estimate the probability of machine failure. It integrates a predictive model developed in Python with a Flask application, allowing users to register equipment, manage maintenance records, review alerts, and obtain failure predictions.

Industrial Context

Industrial equipment operates under different conditions involving temperature, rotational speed, torque, and component wear. Changes in these operating conditions may be associated with equipment failures.

Unexpected failures can interrupt production processes, increase maintenance expenses, and affect operational efficiency. Predictive maintenance uses equipment information to support more informed maintenance decisions.

02. Business Problem

Problem Statement

Industrial maintenance teams may face difficulties identifying potential equipment failures before they occur. When maintenance activities depend mainly on fixed schedules or responses after a failure, equipment problems may remain undetected until they affect operations.

This project addresses the challenge by developing a data-driven system capable of analyzing operating conditions and estimating the likelihood of machine failure.

Business Need

Provide a technological tool that helps maintenance personnel identify possible failure risks, review equipment information, and support maintenance planning using Machine Learning predictions.

03. Business Objectives

General Objective

Develop a predictive maintenance system that integrates Machine Learning and web technologies to estimate potential industrial equipment failures based on operating data and support maintenance decision-making.

Specific Objectives

  • Analyze the AI4I 2020 Predictive Maintenance Dataset.
  • Identify relevant variables associated with machine failure.
  • Develop and train classification algorithms.
  • Evaluate model performance using appropriate metrics.
  • Integrate the selected model into a Flask application.
  • Provide equipment management, maintenance records, and alert functionalities.

05. Machine Learning Objectives and Questions

Machine Learning Problem Definition

The Machine Learning component is formulated as a supervised binary classification problem. The model analyzes machine operating conditions and predicts whether a failure is associated with the observation.

  • Learning type: Supervised Learning.
  • Task: Binary Classification.
  • Target variable: Machine failure.
  • Class 0: No machine failure.
  • Class 1: Machine failure.
  • Selected algorithm: Random Forest Classifier.

Questions the Model Should Answer

  • Does the supplied operating information indicate a possible machine failure?
  • What probability does the model assign to the failure class?
  • How effectively can the model identify failure observations?
  • How reliably can it distinguish failure observations from non-failure observations?

Expected Model Output

The prediction module returns an estimated failure probability and a risk classification. The application uses this information to display Low, Medium, or High risk levels.

These outputs are intended to support decision-making. They do not establish that a machine will fail at a specific future time and do not replace professional equipment inspection.

07. Data Source

AI4I 2020 Predictive Maintenance Dataset

The project uses the AI4I 2020 Predictive Maintenance Dataset. It contains simulated industrial data designed to represent equipment operating conditions and machine failure events.

The dataset provides a structured source for developing and evaluating the predictive classification model. However, its simulated nature must be considered when interpreting results and assessing real-world applicability.

  • Dataset file: ai4i2020.csv
  • Number of observations: 10,000
  • Number of columns: 14
  • Target: Machine failure
  • Data format: CSV

10. Initial Data Exploration

Exploratory Data Analysis

Initial data exploration helps understand the distribution of the variables, examine operating measurements, and identify characteristics that may influence the modeling process.

  • Examine the distribution of machine failures and non-failures.
  • Review air and process temperature measurements.
  • Examine rotational speed and torque values.
  • Analyze the distribution of tool wear.
  • Explore the relationship between operating variables and machine failure.
  • Identify class imbalance in the target variable.

Failure Distribution

The dataset contains 9,661 observations without machine failure and 339 observations with failure. This represents an imbalanced target distribution.

Operating Variables

Temperature, rotational speed, torque, and tool wear describe the operating conditions represented in the dataset.

Interpretation: The class imbalance makes it important to evaluate failure detection using recall, precision, and F1-score rather than accuracy alone.

12. Feasibility, Limitations and Risks

Technical Feasibility

The project is technically feasible using Python, Pandas, Scikit-learn, Flask, and the available dataset. The trained model can be integrated into the web application to process equipment measurements and return predictions.

  • Python provides the environment for data preparation and model development.
  • Scikit-learn supports preprocessing, training, and evaluation.
  • Flask provides the web application and prediction interface.
  • Joblib allows the trained pipeline to be saved and loaded.

Organizational Feasibility

The application is designed to support maintenance technicians and managers by centralizing equipment information and displaying predictive results. A real organizational implementation would require user training, agreement on maintenance workflows, access to reliable equipment measurements, and defined responsibilities for reviewing predictions.

These organizational arrangements are proposed considerations. They have not been validated through deployment in an industrial organization.

Dataset and Project Limitations

  • The dataset is based on simulated industrial operating conditions.
  • Its observations may not represent every type of real industrial equipment.
  • The failure patterns do not cover every possible real-world failure.
  • The minority failure class contains only 339 observations.
  • Model performance depends on the quality and representativeness of available data.
  • Additional testing with real operational data is necessary before production use.

Potential Risks and Mitigation

Risk Potential Impact Proposed Mitigation
False negative predictions A possible failure may not be identified. Monitor recall and maintain professional inspections.
False positive predictions Unnecessary inspections may be considered. Review precision and confirm predictions with technicians.
Simulated training data Results may not generalize to real equipment. Validate with real operational data before production use.
Changes in operating conditions Model performance may degrade. Monitor input data and periodically review model performance.
