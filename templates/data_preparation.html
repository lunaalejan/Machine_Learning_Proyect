CRISP-ML · PHASE 02

Data Engineering

This phase explains how the AI4I 2020 dataset is prepared for predictive modeling. It covers data inspection, quality assessment, feature selection, preprocessing, target preparation, data partitioning, and leakage prevention.

01. Data Preparation Overview

Purpose of Data Engineering

Data Engineering prepares the original dataset so that its variables can be used consistently by Machine Learning algorithms.

The process includes inspecting data quality, selecting relevant variables, encoding categorical data, scaling numerical measurements, preparing the target variable, and separating the data for model development and independent evaluation.

Preparation Objective

Create a consistent input dataset containing relevant machine operating variables and the Machine failure target, while ensuring that preprocessing is fitted without using information from the independent test set.

Outlier Analysis and Limitations

Numerical descriptive statistics were reviewed as part of the initial data inspection. However, the current training script does not implement a dedicated statistical outlier detection or removal procedure.

Data quality limitation: The absence of missing and duplicated records does not independently guarantee that every measurement is physically valid. Further validation against real equipment operating ranges would be required before production use.

Feature Engineering Decisions

The current implementation does not create additional mathematical variables, interaction terms, or derived operating indicators. Instead, it uses the six selected original features and applies the preprocessing transformations required by the machine learning models.

This approach keeps the input structure consistent with the prediction interface, which receives the same six variables.

Information leakage prevention: Failure mode indicators are not used as input features because they describe failure-related outcomes. Excluding them helps prevent the model from receiving information that would not be appropriate as a prediction input.

05. Data Transformation and Preprocessing

Categorical Feature Encoding

The Type variable is categorical. The training pipeline applies OneHotEncoder with handle_unknown="ignore" to represent its categories numerically.

This configuration allows the transformation to handle categories that were not observed during fitting without raising an encoding error.

OneHotEncoder( handle_unknown="ignore" )

Numerical Feature Scaling

Numerical operating measurements are processed using StandardScaler. This transformation standardizes numerical features based on the mean and standard deviation learned from the training data.

StandardScaler()

ColumnTransformer and Pipeline

A ColumnTransformer applies the appropriate transformation to categorical and numerical variables. Both transformations are integrated with the classifier in a single Scikit-learn Pipeline.

preprocessor = ColumnTransformer( transformers=[ ( "categorical", OneHotEncoder(handle_unknown="ignore"), categorical_features ), ( "numerical", StandardScaler(), numerical_features ) ] ) pipeline = Pipeline( steps=[ ("preprocessor", preprocessor), ("classifier", classifier) ] )

Why use a Pipeline? The preprocessing steps and classifier are managed together. During training and cross-validation, transformations are fitted within each training partition. This helps prevent information leakage from validation or test observations.

06. Target Variable Preparation

Machine Failure Classification

The target variable is Machine failure. The prediction task is defined as binary classification, with two possible outcomes: no machine failure (0) and machine failure (1).

Class imbalance: The dataset contains substantially more non-failure observations than failure observations. This imbalance is considered during model development. The three classifiers use class_weight="balanced", and evaluation includes Precision, Recall, F1-score, and ROC-AUC rather than relying on accuracy alone.

07. Training and Testing Split

Dataset Partitioning

The dataset is divided into training and testing subsets before model fitting. The training subset is used for model development, while the testing subset is reserved for final independent performance evaluation.

8,000 Training records · 80%
2,000 Testing records · 20%
42 Random state
Yes Stratified split
X_train, X_test, y_train, y_test = train_test_split( X, y, test_size=0.20, random_state=42, stratify=y )

Partitioning configuration: The training script uses test_size=0.20, random_state=42, and stratify=y. Stratification preserves approximately the same target class proportions in both subsets, and the random state supports reproducibility.

08. Cross-Validation Preparation

Stratified K-Fold Configuration

After the training and testing split, the training subset is used for five-fold stratified cross-validation. This procedure evaluates model performance across multiple training and validation partitions.

5 Cross-validation folds
Yes Shuffling enabled
42 Random state
F1 Model selection metric
cv = StratifiedKFold( n_splits=5, shuffle=True, random_state=42 )

The preprocessing pipeline is evaluated within each fold. This means the encoder and scaler learn their parameters from the corresponding training partition rather than from the complete dataset.

Important distinction: Cross-validation is performed on the training subset. The independent test subset is not used during this process and remains reserved for the final evaluation.

09. Preprocessing and Leakage Prevention

Training-Only Preprocessing

The preprocessing transformations are included inside the model Pipeline. When the pipeline is fitted, OneHotEncoder and StandardScaler learn their transformation parameters from the data supplied to the fitting process.

During cross-validation, Scikit-learn evaluates separate pipeline instances across the training folds. For final model fitting, the pipeline is fitted using X_train and y_train. The independent X_test subset is used only after training for final evaluation.

# Fit the selected pipeline on training data pipeline.fit(X_train, y_train) # Evaluate on the independent test data predictions = pipeline.predict(X_test)

Data Leakage Control

The test subset is not used to fit preprocessing transformations or train the final model. Keeping preprocessing inside the Pipeline provides a consistent and reproducible workflow and helps reduce the risk of data leakage.

11. Data Engineering Summary

Phase Conclusion

The Data Engineering phase established the preparation workflow for the AI4I 2020 dataset. The process includes data inspection, feature selection, categorical encoding, numerical scaling, target preparation, and an 80/20 stratified partition.

The training implementation uses ColumnTransformer and Pipeline to apply OneHotEncoder and StandardScaler consistently. These transformations are fitted within the training process, helping prevent information leakage into validation and test data.

Five-fold Stratified K-Fold cross-validation is applied to the training subset to compare model performance. The independent test subset remains reserved for final evaluation.

The dataset contains 10,000 observations, with 9,661 non-failure records and 339 failure records. Its class imbalance is considered during model development and evaluation.

No additional derived features, dedicated outlier treatment procedure, or separate before-and-after transformation report have been implemented in the current training script. These are identified as possible future improvements.

The prepared data and preprocessing pipeline provide the foundation for the next phase: Model Engineering.
