CRISP-ML · PHASE 05

Model Deployment

This phase describes the integration and deployment of the trained Random Forest model into the Predictive Maintenance System developed with Flask. It documents the application architecture, model integration, execution environment, user instructions, and deployment maintenance procedures.

01. Deployment Overview

Purpose of Model Deployment

Model Deployment makes the trained Machine Learning model available through the Flask web application. The selected Random Forest classifier was trained using the AI4I 2020 Predictive Maintenance dataset.

The trained model is serialized and stored as a Joblib file. The prediction module loads this artifact to estimate the probability of equipment failure from user-provided operating conditions.

Deployment Objective

Integrate the selected model into a functional web application so users can enter equipment operating information, obtain a predicted failure probability, and review the corresponding risk classification.

Database Integration

The application uses SQLite and SQLAlchemy to manage equipment, maintenance records, alerts, and predictions. Each generated prediction is associated with the selected registered equipment.

Prediction records include the estimated failure probability, risk level, model version, and prediction timestamp through the Prediction database model.

03. Model Integration

The trained model is stored using Joblib inside the machine_learning/model directory. The prediction module loads the saved artifact when a prediction is requested.

Prediction Function

The predict_failure() function receives equipment information as a dictionary. It verifies that all six required features are available, prepares the input as a Pandas DataFrame, and calculates the failure probability using predict_proba().

result = predict_failure(equipment_data)

04. Prediction Input Features

Required Equipment Information

The prediction process requires six input variables corresponding to the features used during model training.

Input Variable Description Data Type

Process temperature [K] Equipment process temperature. Numerical
Rotational speed [rpm] Machine rotational speed. Numerical
Torque [Nm] Machine operating torque. Numerical
Tool wear [min] Accumulated tool wear time. Numerical

05. Prediction Output

Model Results

After receiving the six input variables, the model estimates the probability of machine failure. The application converts this probability into a percentage and assigns a risk category.

Risk Level Failure Probability Interpretation
Low Below 30% Lower estimated failure risk.
Medium 30% to below 70% Moderate estimated failure risk.
High 70% or higher Higher estimated failure risk.

Important: These categories are application-defined thresholds. They are not independently validated industrial maintenance intervention thresholds. Predictions should support, not replace, professional inspection and maintenance decisions.

06. Deployment Workflow

Application Prediction Process

  • The user accesses the Predictive Maintenance System.
  • The user registers equipment if it has not already been registered.
  • The user opens the Predictions section.
  • The user selects registered equipment.
  • The user enters the six required operating variables.
  • Flask validates the submitted information.
  • The prediction module loads and executes the trained model.
  • The application displays the estimated failure probability and risk level.
  • The prediction is stored in the database and becomes available in prediction history.

08. Installation and Execution Instructions

Local Execution

The following commands describe the basic procedure for running the project locally on a Windows computer.

  • Open the project folder in the terminal.
  • Activate the Python virtual environment.
  • Install the project dependencies.
  • Ensure the trained model artifact is available.
  • Start the Flask application.
.venv\Scripts\activate
pip install -r requirements.txt
python app.py

After starting the application, open the local address displayed by Flask in the terminal, normally http://127.0.0.1:5000/.

Model Artifact Requirement

The file failure_model.joblib must be present in machine_learning/model/. If the artifact is missing, the model must be trained using the training script before prediction functionality can be used.

09. User Guide

How to Use the System

  • Access the web application using the published URL.
  • Open the Application section and register the equipment information.
  • Navigate to the Predictions section.
  • Select the equipment to be evaluated.
  • Enter the machine type and the five numerical operating measurements.
  • Submit the form to generate the prediction.
  • Review the failure probability and risk classification.
  • Consult Prediction History to review previously stored results.
  • Use the Dashboard to review system statistics and prediction summaries.

Usage consideration: Input measurements should be obtained from reliable equipment records or appropriate monitoring instruments. Incorrect or unrealistic input values can affect prediction usefulness.

12. Error Handling and Reliability

Input Validation

The application checks required equipment information, numeric input values, finite numbers, valid machine types, and selected equipment records before prediction.

Model Availability

The prediction module verifies that the serialized Joblib model exists. If the model file is unavailable, a FileNotFoundError is raised and handled by the Flask route.

Database Reliability

Prediction records are saved through SQLAlchemy. When an exception occurs during the prediction process, the application rolls back the database transaction.

Error Reporting

Unexpected prediction errors are recorded through the Flask application logger, while users receive a general error message instead of internal technical details.

13. Deployment Maintenance and Updates

Model Update Procedure

  • Review the model's evaluation results and new available data.
  • Prepare and validate an updated training dataset.
  • Train and evaluate the candidate model.
  • Compare its performance with the currently deployed model.
  • Save the approved model artifact using the expected file path.
  • Test prediction functionality before publishing the update.
  • Deploy the updated application and verify its operation.

Incident Reporting and User Feedback

Users should report incorrect results, missing equipment information, unexpected application behavior, or problems accessing the system.

Reports should include the date, affected equipment identifier, description of the issue, and relevant error information. Technical personnel should review the report, reproduce the issue when possible, document the resolution, and verify the correction.

User feedback can also help identify improvements in the interface, input validation, and prediction workflow.

Operational limitation: Model retraining, automatic model replacement, and continuous performance monitoring are not claimed as automated deployment features. They require a documented review and approval process.

Phase Conclusion

The Model Deployment phase integrates the selected Random Forest classifier into the Flask-based Predictive Maintenance System.

The application receives six equipment operating variables, validates the submitted information, generates a failure probability, and assigns a risk category. Prediction results are stored in the database and made available through the application interface.

The system is published through Render and provides a functional demonstration of the Machine Learning model. The deployment documentation also establishes user instructions, execution requirements, a proposed integration plan, and procedures for future updates and incident reporting.
