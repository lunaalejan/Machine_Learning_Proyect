CRISP-ML · PHASE 05

Model Deployment

This stage describes the integration of the trained Random Forest model into the Predictive Maintenance System developed with Flask. It explains how equipment information is received, processed, and used to generate machine failure predictions through the web application.

01. Deployment Overview

Purpose of Model Deployment

Model Deployment makes the trained Machine Learning model available through the Flask web application. The Random Forest classifier, previously trained using the AI4I 2020 dataset, is serialized and stored as a Joblib file. The application loads this model and uses it to process equipment operating conditions and estimate the probability of machine failure.

Deployment Objective

Integrate the trained model into the web application, allowing users to provide equipment information and receive a predicted failure probability and corresponding risk classification.

03. Model Integration

Trained Model

The trained model is stored using Joblib in the machine_learning/model directory. The prediction module loads this file when a prediction request is processed. This allows the Flask application to reuse the trained model without executing the training process every time a user makes a prediction.

Prediction Function

The predict_failure function receives equipment information as a dictionary, validates the required features, prepares the input as a Pandas DataFrame, and calculates the probability of machine failure using predict_proba().

result = predict_failure(equipment_data)

04. Prediction Input Features

Equipment Information

The prediction process requires six input variables corresponding to the features used during model training.

Input Variable Description Data Type
Type Equipment product quality category. Categorical
Air temperature [K] Ambient air temperature. Numerical
Process temperature [K] Equipment process temperature. Numerical
Rotational speed [rpm] Machine rotational speed. Numerical
Torque [Nm] Machine operating torque. Numerical
Tool wear [min] Accumulated tool wear time. Numerical

05. Prediction Output

Model Results

After receiving the six input variables, the model estimates the probability of machine failure. The prediction function converts this probability into a percentage and assigns a risk category according to the thresholds defined in the application.

Risk Level Failure Probability Interpretation
Low Below 30% Lower estimated failure risk.
Medium 30% to below 70% Moderate estimated failure risk.
High 70% or higher Higher estimated failure risk.

Important: These risk categories are application-defined thresholds based on the predicted probability. They are not independently validated maintenance intervention thresholds.

06. Deployment Process

Application Workflow

  • The user accesses the Predictive Maintenance web application.
  • The user enters the required equipment operating conditions.
  • The Flask application receives and validates the submitted information.
  • The prediction module loads the trained Random Forest model.
  • The model calculates the estimated failure probability.
  • The application displays the probability and risk classification.

08. Error Handling and Reliability

Input Validation

The prediction module checks that the equipment information is provided as a dictionary and that all six required features are available before making a prediction.

Model Availability

Before loading the trained model, the prediction module verifies that the Joblib file exists. If the model file is unavailable, a FileNotFoundError is raised.

Reliability consideration: Additional application-level error handling should ensure that unexpected failures are reported clearly to users without exposing sensitive technical information.

09. Application Availability

Web Application Access

The Predictive Maintenance System is developed as a Flask web application. Its deployment environment makes the system accessible through a web browser without requiring users to execute the Machine Learning scripts manually.

  • Web-based application interface.
  • Flask routes for application navigation.
  • Integration with the trained model.
  • Equipment information input and prediction workflow.

Deployment Result

The trained Random Forest model is integrated into the Predictive Maintenance application, allowing the prediction functionality to be accessed through its web interface.

Phase Conclusion

The Model Deployment phase describes how the trained Random Forest classifier is integrated into the Flask application. The model is stored using Joblib and loaded through the prediction module to process six equipment input variables. The application calculates a failure probability and assigns a risk level based on predefined thresholds. This integration makes the predictive functionality available through the web application and provides the foundation for the final Monitoring and Maintenance phase.
